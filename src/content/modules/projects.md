A project is a scoped campaign of work — a shutdown, remediation package, maintenance campaign or new build — that references assets rather than owning them. When the next project starts on the same plant, the asset's inspection history carries straight on.

Each project records its client, site, region, timezone, currency and status, and every list in the platform is scoped to the project you have selected. A work-type classification you configure decides which approvals, ITP templates, documents and workflows apply, and a closeout checklist keeps a project from being archived while holds, NCRs or certificates remain open.

## Key features

- Projects with code, client, site, region, timezone, currency and status
- Header project switcher, with every list scoped to the selected project
- Sites with GPS location under each project
- Project membership, roles and a participant directory with party roles
- Project-asset scope baseline with change history, baseline versus current view and diff export
- Configurable work-type classification that selects approvals, ITP templates, documents and workflows
- Project templates by work type carrying ITP sets, forms, roles and approval chains
- Per-project numbering schemes with client prefixes
- Project settings for units, calendar, enabled modules and terminology overrides
- Closeout checklist that blocks archive, with external access expiring on close
